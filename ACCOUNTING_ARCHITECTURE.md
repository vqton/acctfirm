## Architecture Choices

1. **Framework-Free Design**: 
   - No external frameworks (Symfony/Laravel)
   - Build on PHP's native features and minimal dependencies
   - Use Composer only for PSR-4 autoloading and dependency management

2. **Design Patterns**: 
   - Domain-Driven Design (DDD) for clear separation of accounting domain logic
   - CQRS to separate transaction processing from reporting queries
   - Hexagonal Architecture to isolate domain from external concerns
   - Service Layer pattern for business logic
   - Repository pattern for data access abstraction

3. **Database Schema**: 
   - Normalized schema for double-entry accounting
   - Core tables: Accounts, Transactions, LedgerEntries
   - Each transaction creates two ledger entries (debit and credit)
   - ACID compliance with database transactions
   - Use PDO for database access (native PHP extension)

4. **Security Requirements**:
   - HTTPS everywhere
   - Input validation and sanitization (using native PHP functions)
   - Parameterized queries with PDO to prevent SQL injection
   - Role-Based Access Control (RBAC) with principle of least privilege
   - Encryption of sensitive financial data at rest (AES-256 using OpenSSL)
   - Comprehensive logging and monitoring for all financial transactions
   - Compliance with financial regulations (GDPR, SOX, PCI-DSS)

5. **Routing**: 
   - Custom lightweight router in `src/Accounting/Interfaces/HTTP/Router.php`
   - Maps HTTP requests to controllers using regex-based routing
   - No external routing libraries

6. **Dependency Injection**: 
   - Simple container implementation in `config/services.php`
   - Manual instantiation of dependencies
   - No external DI containers

7. **Testing**: 
   - Comprehensive test suite with PHPUnit (only dependency)
   - Unit tests for domain logic
   - Feature tests for transaction flows

## Implementation Notes

- Use PSR-4 autoloading via Composer for all application code
- Implement dependency injection manually through constructor injection
- Use PHP's native PDO for database access
- Use PHP's built-in session management for authentication
- Use OpenSSL extension for encryption
- Implement logging with native file system operations
- Use native PHP functions for validation (filter_var, preg_match, etc.)
- Implement CSRF protection with token-based validation
- Use native PHP sessions with secure settings
- Implement rate limiting with file-based or memory-based counters
- Use native PHP mail functions or SMTP libraries for notifications
- Build CLI commands using PHP's built-in CLI functionality

This architecture ensures the accounting system is secure, maintainable, and reliable for handling sensitive financial data while avoiding framework dependencies and vendor lock-in.
